Core Concepts

📦 Repository (repo)

A folder that Git tracks. It stores your project files and the entire history of every change ever made.

📸 Commit

A saved snapshot of your files at a specific point in time. Think of it as a save game you can always return to.

🌿 Branch

A separate line of development. Work on a new feature in its own branch without breaking the main code.

🎭 Staging Area

A waiting room where you place changes before committing. Choose exactly what goes into each snapshot.

🔀 Merge

Combining two branches together. When your feature is ready, merge it back into main.

☁️ Remote

A copy of your repo hosted online (e.g. GitHub). Push to share your work; pull to download others'.

📥 Clone

Downloading a complete copy of a remote repository — history and all — onto your local machine.

🗺️ HEAD

A pointer to your current position in the repository — usually the latest commit on your current branch.

The Git Workflow

Every day as a developer, you follow this cycle:

# 1. Make changes to your files (just edit them normally)

# 2. Check what changed
git status

# 3. Stage the changes you want to save
git add filename.txt         # stage one file
git add .                    # stage everything

# 4. Commit with a descriptive message
git commit -m "Add login page"

# 5. Push to GitHub so others can see it
git push origin main
⚠️ Golden rule: Commit often and write clear messages. Future-you will be very grateful.

Hands-On Exercises

Open your terminal and follow along. Each exercise builds on the last.

EX 1

Create Your First Repository

Start from scratch — create a folder and turn it into a Git repo.

  1. Open your terminal and navigate somewhere convenient (e.g. your Desktop).
  2. Create a new folder and enter it: 
    mkdir my-first-repo
cd my-first-repo
  3. Initialise Git: 
    git init
Initialized empty Git repository in .../my-first-repo/.git/
  4. Create a file and write something in it: 
    echo "Hello, Git!" > README.txt
  5. Check what Git sees: 
    git status
Untracked files:
  README.txt
EX 2

Make Your First Commit

Stage your file and save a snapshot of your work.

  1. Stage the file: 
    git add README.txt
  2. Confirm it's staged (notice it turns green in many terminals): 
    git status
Changes to be committed:
  new file: README.txt
  3. Commit it: 
    git commit -m "Initial commit: add README"
[main (root-commit) a1b2c3d] Initial commit: add README
 1 file changed, 1 insertion(+)
  4. View the commit log: 
    git log --oneline
a1b2c3d Initial commit: add README
EX 3

Create and Switch Branches

Work on a new feature without touching the main branch.

  1. Create a new branch called feature/greeting: 
    git checkout -b feature/greeting
Switched to a new branch 'feature/greeting'
  2. Edit README.txt — add a second line: "Learning Git is fun!"
  3. Commit the change: 
    git add README.txt
git commit -m "Add greeting line to README"
  4. Switch back to main and notice the file is unchanged there: 
    git checkout main
cat README.txt
Hello, Git!
  5. Merge your feature in: 
    git merge feature/greeting
Updating a1b2c3d..e4f5g6h
Fast-forward
 README.txt | 1 +
EX 4

Time Travel with git diff & git log

Inspect what changed and when.

  1. Edit README.txt again — add a third line: "Version control is powerful." But do not commit yet.
  2. See exactly what's different from the last commit: 
    git diff
- Learning Git is fun!
+ Learning Git is fun!
+ Version control is powerful.
  3. See the full commit history with dates and authors: 
    git log
  4. Stage and commit your new line, then try: 
    git log --oneline --graph --all
    This shows a visual tree of all branches and commits.

Command Cheat Sheet

CommandWhat it does
git initInitialise a new repository in the current folder
git clone <url>Copy a remote repository to your machine
git statusShow what's changed, staged, or untracked
git add <file>Stage a specific file for the next commit
git add .Stage all changes in the current directory
git commit -m "msg"Save a snapshot with a descriptive message
git log --onelineView compact commit history
git diffShow unstaged changes line-by-line
git branchList all local branches
git checkout -b <name>Create and switch to a new branch
git checkout <name>Switch to an existing branch
git merge <branch>Merge a branch into the current one
git push origin <branch>Upload commits to the remote repository
git pullDownload and merge the latest remote changes
git stashTemporarily shelve changes without committing

Key Takeaways

The core ideas to lock in before you close this page:

git init

Every project starts here. One command turns any folder into a tracked repository.

Stage → Commit

Changes are a two-step process: add to stage, then commit to save permanently.

Branches

Always work in a branch for new features. Keep main clean and working.

Commit messages

Write why you made the change, not just what. Future collaborators (and future-you) will thank you.

Remote = backup

Push to GitHub regularly. Local disasters (deleted folder, crashed laptop) can't touch your remote history.

git status

Your best friend. Run it constantly. It always tells you what to do next.

Merge conflicts

Don't panic. Open the file, look for the <<<<<<< markers, decide what to keep, save, and commit.

Commit often

Small, frequent commits are easier to understand, review, and undo than one giant save.
