0. What you're about to build

An LLM is, mechanically, an embarrassingly simple object: given some text, predict the next token. Repeat that one trick a few hundred times and you get an essay. Train it on the whole internet and you get the engine behind modern AI coding agents like Auggie.

This tutorial strips the idea down to its bones. We'll train a model on a tiny chunk of Shakespeare, and we'll do it character by character so you can see every number flow. By the end of Chapter 5 you'll have built the same architecture (just shrunk by ~10,000×) as the one powering GPT-4.

The companion code lives in tuts/llm-from-scratch/ alongside this page. Open both side-by-side as you read.

The whole journey on one page

  • Ch 1. Turn characters into integers (no model yet).
  • Ch 2. Predict next character by counting — gives gibberish but with real letter statistics.
  • Ch 3. Same idea, but learned with PyTorch + gradient descent.
  • Ch 4. Add self-attention so the model can see context.
  • Ch 5. Stack transformer blocks. This is GPT, in miniature.
  • Ch 6. Steer the output with temperature and top-k sampling.

1. Vocabulary: characters as numbers

Neural networks do arithmetic on numbers, not strings. So the very first job is a tokenizer — a function that turns text into a sequence of integers (and back). For real LLMs the tokens are sub-word pieces ("th", "ough", "##ing") learned by an algorithm called BPE. We're going to do the dumbest possible version: one token = one character.

Build the vocabulary

src/ch1_vocab.py 
from pathlib import Path

DATA = Path(__file__).resolve().parent.parent / "data" / "input.txt"
text = DATA.read_text(encoding="utf-8")

# The vocab is just every unique character, sorted.
chars = sorted(set(text))

stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for ch, i in stoi.items()}

def encode(s): return [stoi[c] for c in s]
def decode(ids): return "".join(itos[i] for i in ids)

Run it

$ uv run src/ch1_vocab.py
corpus length : 5,585 characters
vocabulary    : 58 unique characters

encode('To be, or not to be')
  -> [29, 47, 1, 35, 38, 4, 1, 47, 50, 1, 46, 47, 52, 1, 52, 47, 1, 35, 38]
decode(...)
  -> 'To be, or not to be'
How real LLMs differ: GPT-4 has a vocabulary of ~100,000 tokens instead of 58. The tokens are sub-word pieces learned by Byte-Pair Encoding (BPE), so common words like "the" get a single token while rare words split into several. The encode/decode interface stays exactly the same.
Why use sub-word tokens (~50,000 vocab) instead of just characters (~100 vocab) in real LLMs?

2. Bigram by counting: probability without learning

Before we touch a neural network, let's build the laziest possible language model: count which characters follow which, then sample from that distribution.

This will be terrible at writing English. But the output will already have the texture of English — lots of "th", "he", "in"; very few "qx", "zk". Everything we do from Chapter 3 onwards is just a fancier way to learn this same idea.

Count followers, then sample

src/ch2_bigram_counts.py 
import random
from collections import Counter, defaultdict

counts = defaultdict(Counter)
for a, b in zip(text, text[1:]):
    counts[a][b] += 1

def sample_next(prev):
    c = counts[prev]
    return random.choices(list(c.keys()), weights=list(c.values()))[0]

Generated sample:

💡 Notice "th" appears constantly and "qx" never does. The model captured real English bigram statistics — and we wrote zero machine learning code.
The big limitation: a bigram model only looks at the previous character to pick the next one. It has no idea what was 5 characters ago. That's why the output looks like word-fragments — coherent two-character pairs glued randomly together. To do better, the model needs memory. That's what attention will give us.
Our counting bigram has effectively memorised a 58×58 table of probabilities. Why can't we just scale this up to "fix" the gibberish?

3. Same bigram, but learned

Chapter 2 used hand-counted probabilities. We'll now express the exact same model as a tiny neural network and let gradient descent fill in the table for us. This looks like a sideways move — and at first it is — but it sets up the scaffolding (loss, optimiser, batched data) we'll reuse for the rest of the chapters.

The model is a single embedding table

src/ch3_bigram_learned.py 
class BigramModel(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        # Row i holds the (unnormalised) next-char distribution given char i.
        self.token_embedding = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        logits = self.token_embedding(idx)        # (B, T, vocab)
        if targets is None: return logits, None
        B, T, V = logits.shape
        loss = F.cross_entropy(logits.view(B*T, V), targets.view(B*T))
        return logits, loss

The training loop

opt = torch.optim.AdamW(model.parameters(), lr=1e-2)
for step in range(3001):
    xb, yb = get_batch(data)         # random 32×8 chunks of text
    _, loss = model(xb, yb)
    opt.zero_grad(set_to_none=True)
    loss.backward()                 # backprop
    opt.step()                      # nudge weights downhill

💡 The loss is cross-entropy: roughly "how surprised was the model by the correct next character?" Lower = better. Random guessing would give ln(58) ≈ 4.06, so dropping to ~2.45 means the model has captured real structure.
Why bother going to PyTorch? Because every piece we add from now on — attention, MLPs, residuals — is just more layers in front of that same cross_entropy call. The training loop never changes again.

4. Self-attention: giving the model memory

Until now our model can only see the current character. To predict "e" after "th", or "liet" after "Ju", it needs to look further back. Self-attention is the mechanism every transformer uses to do this.

The big idea in 3 bullets

  • Every token emits three vectors: a query, a key, and a value.
  • The attention weight from token i to token j is softmax(qi · kj) — high when query and key point the same way.
  • Token i's new representation is the weighted sum of all earlier value vectors. A causal mask blocks attention to future tokens.

The single-head implementation

src/ch4_attention.py 
class SelfAttentionHead(nn.Module):
    def __init__(self, n_embd, head_size, block_size):
        super().__init__()
        self.key   = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        k, q, v = self.key(x), self.query(x), self.value(x)
        wei = q @ k.transpose(-2,-1) * k.size(-1)**-0.5          # (B,T,T)
        wei = wei.masked_fill(self.tril[:T,:T]==0, float("-inf"))   # no peeking
        wei = F.softmax(wei, dim=-1)
        return wei @ v                                            # (B,T,head_size)
💡 The tril lower-triangular mask is what makes the model causal — token i can never see tokens after i. Without it, training would leak the answer and the model would learn nothing.

5. The full transformer block

A single attention head is doing real work, but four refinements turn it into the standard GPT building block. Stack two of these on top of each other and you have, in miniature, the same architecture as the model behind ChatGPT.

The four upgrades

  • Multi-head attention. Run several heads in parallel; concat outputs. One head might track punctuation, another speaker names.
  • Feed-forward (MLP). Attention moves info between positions; the MLP processes info within a position.
  • Residual connections. Add each sub-layer's output back to its input — lets gradients flow around layers.
  • LayerNorm. Normalise each position's vector before the sub-layer. Training stability.

One Transformer block

src/ch5_transformer.py 
class Block(nn.Module):
    def __init__(self, n_embd, n_head):
        super().__init__()
        head_size = n_embd // n_head
        self.sa  = MultiHead(n_head, head_size)
        self.ff  = FeedForward(n_embd)
        self.ln1 = nn.LayerNorm(n_embd)
        self.ln2 = nn.LayerNorm(n_embd)

    def forward(self, x):
        x = x + self.sa(self.ln1(x))   # residual around attention
        x = x + self.ff(self.ln2(x))   # residual around MLP
        return x

The whole "mini-GPT"

class MiniGPT(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.token_embedding    = nn.Embedding(vocab_size, N_EMBD)
        self.position_embedding = nn.Embedding(BLOCK_SIZE, N_EMBD)
        self.blocks = nn.Sequential(*[Block(N_EMBD, N_HEAD) for _ in range(N_LAYER)])
        self.ln_f   = nn.LayerNorm(N_EMBD)
        self.lm_head = nn.Linear(N_EMBD, vocab_size)

6. Steering the output: temperature & top-k

Up to now we've sampled directly from softmax(logits). Two simple knobs — both exposed by every commercial LLM API — change the feel of the output dramatically.

The sampling function

src/ch6_generate.py 
def generate(model, idx, max_new, temperature=1.0, top_k=None):
    for _ in range(max_new):
        idx_cond = idx[:, -BLOCK_SIZE:]
        logits, _ = model(idx_cond)
        logits = logits[:, -1, :] / max(temperature, 1e-8)
        if top_k is not None:
            v, _ = torch.topk(logits, top_k)
            logits[logits < v[:, [-1]]] = float("-inf")
        probs = F.softmax(logits, dim=-1)
        nxt = torch.multinomial(probs, num_samples=1)
        idx = torch.cat([idx, nxt], dim=1)
    return idx

7. What you actually built

Stand back and look at the six files together. You wrote, end to end:

Tokenizer

Character ↔ integer mapping. Real LLMs use BPE for ~50,000-token vocabularies; the interface is the same.

Embeddings

Lookup table that turns token IDs into dense vectors. Position embeddings encode order.

Self-attention

Query/key/value triple. Causal mask. Softmax of qkᵀ. The same maths in GPT-4.

Transformer block

Multi-head attention + MLP, both with residual + LayerNorm. The repeating unit of every modern LLM.

Training loop

Cross-entropy loss, AdamW optimiser, batched random chunks. The same scaffold across every chapter.

Sampling

Temperature + top-k. The same knobs every chat API exposes.

Where to go next

  • Swap the dataset. Replace data/input.txt with anything — your own writing, a book, code. Re-run Chapter 5. Watch the style shift.
  • Scale it up. Bump N_LAYER=4, N_EMBD=192, BLOCK_SIZE=128. Train for 10k steps. The loss will plateau lower and the output will pick up real word structure.
  • Move to GPU. Add device = "cuda" if torch.cuda.is_available() else "cpu" and .to(device) on the model + batches. 100× faster.
  • Read nanoGPT. Karpathy's repo is essentially this tutorial, polished. Now that you've built it once, you'll read it like prose.
