## Project summaries

### 01 · Mood Journal ⭐⭐
A daily mood tracker where users log their mood (1–5 with an emoji), add a short note, and view their history as a chart. No backend — everything lives in the browser using localStorage. A great first web app: it covers the core ideas of the web (HTML, CSS, JS) without needing a server or framework.

### 02 · Flashcard App ⭐⭐
A revision tool where students create decks of flashcards, flip them to reveal answers, and track their scores. Includes a basic spaced repetition algorithm — cards you get wrong come back sooner. Built with React, it's a perfect introduction to component-based UI development.

### 03 · Carbon Calculator ⭐⭐⭐
A personal carbon footprint calculator. Users enter their weekly habits (transport, diet, energy use, flights) and see their CO₂ score compared to the UK average, broken down by category. This one has a real-world purpose and is great if anyone on the team is interested in climate.

### 04 · Weather Dashboard ⭐⭐⭐
A live weather app using the free Open-Meteo API (no sign-up needed). Shows current conditions and a 7-day forecast with charts for any UK city. A classic beginner full-stack experience: fetch data from an external API, handle loading and error states, and display it beautifully.

### 05 · Finance Tracker ⭐⭐⭐
A personal income and expense tracker. Add transactions, assign them to categories, view monthly summaries in charts, and set budget warnings. Optionally add a Node.js + SQLite backend for persistent storage. Great if anyone on the team is interested in economics or data.

### 06 · Biodiversity Map ⭐⭐⭐
An interactive map of UK wildlife sightings using the free GBIF (Global Biodiversity Information Facility) API or a bundled CSV dataset. Filter by species, region, and date; view charts of sighting trends. Combines geography, biology, and data engineering in one project.

### 07 · Physics Simulation ⭐⭐⭐⭐
An interactive physics playground with three simulations: projectile motion, orbital mechanics, and a spring-mass system. Real-time animation with parameter sliders and live equation displays. If your team includes physics or maths enthusiasts, this project will make those subjects come alive.

### 08 · Text Analysis Tool ⭐⭐⭐⭐
Paste any text — an essay, a speech, a news article — and get deep analysis: word frequency charts, sentence length distributions, readability scores, keyword extraction, and side-by-side text comparison. The first project that needs both a frontend and a backend. Great for anyone interested in language, linguistics, or data science.

### 09 · AI Study Buddy ⭐⭐⭐⭐
A subject-specific AI tutor powered by an LLM API. Users choose a subject and level, and the app can explain topics, generate quiz questions, mark answers, and create revision summaries. The most modern project in the list — you'll learn how to build AI-powered apps, which is one of the hottest skills in tech right now.

### 10 · Calculus Explainer ⭐⭐⭐⭐⭐
A fully worked-out project with 3D visualisations of calculus concepts (derivatives, integrals, Taylor series) built with React and Three.js, backed by a Python FastAPI server. This is the most complex project and comes with extensive documentation, starter code, and a day-by-day plan. Best for teams with some prior experience.

## How to choose your project

Ask these questions as a team:

1. **What excites us?** Pick something at least one person genuinely wants to build.
2. **What's the right difficulty?** Stretch yourself — but not so far you can't ship anything. When in doubt, go one star harder than feels comfortable.
3. **What subjects does the team know well?** The carbon calculator will be more interesting if someone on the team does Geography. The physics simulation will be more interesting if someone does A-Level Physics.
4. **What do we want to learn?** If the goal is to understand APIs, go for 04, 06, or 09. If it's to understand algorithms, go for 02 or 08. If it's to understand full-stack architecture, go for 08 or 09.

You don't need to know the technologies before you start. The projects are designed to teach you what you need.

---

## What makes a project "done"?

By Day 10, a finished project means:

- **Shipped:** the app runs in a browser and does what it's supposed to do
- **Documented:** the repository has a clear README explaining what the project is, how to run it, and what you built
- **Demoed:** the team can walk through the app in a five-minute presentation and explain the key technical decisions
- **Committed:** all code is in a GitHub repository with meaningful commit history showing who did what

You don't need to have built every feature in the brief. An MVP (Minimum Viable Product) that works is the goal. A complete but buggy app that crashes during the demo is not.
